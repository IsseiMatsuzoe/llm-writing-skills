# Overleaf Editor

ブラウザで開いているOverleaf上の原稿に対して、指定された局所変更だけを一意アンカーの検索とキー入力で反映する試作スキルです。

本スキルは文章の執筆方針や推敲案の検討は扱いません。修正内容は別の執筆スキル等であらかじめ確定させた上で利用します。

## 主な用途と対象外

### 使える場面
- 文中の特定箇所の置換、削除、およびその前後への文字列挿入。
- 作業者またはエージェントが、対象プロジェクトおよびファイルをすでにブラウザで開いている状態での部分編集。

### 使えない場面（対象外）
- ファイル全体の同期や上書き更新。
- プロジェクト内の新規ファイル作成、削除、ファイル名変更などのファイル管理。
- Overleafの履歴（Track Changes）の差分の承認や却下。

## 事前準備と前提条件

1. **指示内容の確定**: 修正対象の原稿箇所の指定と、変更可能な範囲をあらかじめ明確にしておきます。
2. **安全なログイン**: 操作用のアカウントでブラウザに手動ログインしておきます。パスワードや認証情報をチャットやスクリプトに渡さないでください。
3. **CDP接続の確立**: 既存のChromeインスタンスでローカルCDP（Chrome DevTools Protocol）を有効化し、対象プロジェクトおよびファイルが開かれていることを確認します。
4. **排他・待機状態の確保**: 対象ファイルをアクティブタブとして表示し、共同編集者による同時編集を一時停止できる状態で実行します。
5. **実行環境**: Pythonおよび `websockets.sync.client` が必要です。本CLIによる自動インストールは行われません。

### 安全条件と接続仕様
- CDP接続先は既定で `127.0.0.1:9333` です。変更は `--port` オプションでのみ指定可能です。
- CDPには強いブラウザ操作権限があるため、専用プロフィールを使い、ポートを外部ネットワークへ公開しないでください。補助CLIはCookieを読み取らず、新たなアカウント権限も要求しません。
- LinuxおよびWindowsの標準的なCtrlショートカット操作を前提として設計しています。実機検証済み環境はLinux版Chromeのみであり、WindowsおよびmacOSでの動作は未検証です。
- CLI自体はブラウザの起動、ログイン、タブ移動、ページ再読み込み（リロード）は行いません。

## 1. 計画ファイル（plan.json）の作成

読み取り専用のエディタ状態から全文を確認し、変更箇所を特定するための一意アンカーを決定します。

全文と編集指示をローカルの `plan.json` に保存します。なお、「原稿や計画を外部へ送信しない」という説明は本補助CLI自体の通信範囲を指すものであり、このCLIを呼び出すAIサービス全体の機密性を保証するものではありません。計画ファイルには原稿全文が含まれるため、公開リポジトリや共有ログには保存しないでください。

アンカーは、各編集を実行する直前の全文中に完全一致で**1件のみ**存在する必要があります（重複がある場合は周囲の文脈を含めて一意化し、曖昧な状態では進めません）。v0.1の実装では、アンカーは1行の文字列に限られ、改行を含むアンカーは入力前に拒否されます。

```json
{
  "project_url": "https://www.overleaf.com/project/YOUR_PROJECT_ID",
  "file_name": "main.tex",
  "expected_before": "% red bird\n",
  "edits": [
    {"anchor": "red", "replacement": "blue", "mode": "replace"}
  ]
}
```

- `project_url` の `YOUR_PROJECT_ID` は説明用のダミー値です。実際の24桁の16進数プロジェクトIDに置き換えてください。
- `expected_before` は画面表示上の抜粋ではなく、改行コードを含むファイルの全文を指定します。
- `edits` 内の編集操作は配列順に適用され、各ステップのアンカーは更新後の全文に対して都度検証されます。
- `mode` は `replace`（置換）、`before`（直前挿入）、`after`（直後挿入）のいずれかです。
- 削除を行う場合は、`mode` を `replace` にし、`replacement` を空文字列 `""` に設定します。

## 2. 事前確認（dry-run）

原稿を変更する前に、まずdry-runを実行して前提条件を検証します。スキルのディレクトリで実行してください。

```sh
python scripts/overleaf_ui.py plan.json
```

このコマンドでは以下の項目を非破壊で検証します。

- 指定したURLに一致するページタブがブラウザ内に1つだけ存在するか。
- アクティブなファイルタブの名前要素が `file_name` と完全一致しているか。
- エディタ内の全文が `expected_before` と完全に一致しているか。

DOM構造やCodeMirrorの読み取り専用アクセサが取得できない場合は、推測で処理を続行せず直ちに停止します。dry-run実行時は検索や選択などのブラウザ入力は一切送信されず、文書は変更されません。出力中の `after_match` は、dry-runにおいては「全文が変更前と一致していること」を示します。

## 3. 局所編集の実行（apply）

計画内容とdry-runの検証結果を確認した上で、明示的に変更を適用します。

```sh
python scripts/overleaf_ui.py plan.json --apply
```

各編集ステップは以下の手順で厳格に実行されます。

1. 対象URL、アクティブファイル、想定される全文を再確認する。
2. Ctrl+Fで検索バーを開き、フォーカス状態および検索オプションが無効化されていることを確認する。
3. 検索バーでCtrl+Aを実行後、CDPの文字キーイベント経由でアンカー文字列を入力する。
4. EnterおよびEscapeを実行後、エディタ上の実際の選択位置・選択文字列がアンカーと一致するか照合する。
5. 前後への挿入（`before` / `after`）の場合は、ArrowLeftまたはArrowRightで選択状態を解除し、実際のキャレット位置を確認する。
6. 文字キー入力によって編集を反映し、適用後の期待全文と実際のエディタ全文を照合する。
7. 全文の一致が確認できた場合のみ、次の編集ステップへ進む。

DOMのvalue直接書き換え、fill、setValue、CodeMirrorの内部状態やトランザクションへの直接書き込みは行いません。また、クリップボード操作、ファイルアップロード、Replace All（一括置換）、ファイルの作成・削除、エディタ設定の変更も行いません。

## 4. 実行結果の確認と停止条件

CLIの実行結果はJSON形式で出力されます。出力には変更前後の全文一致成否、完了した編集件数、文字入力が開始されたかどうかのフラグ、経過秒数、エラー情報が含まれます。

### 異常停止と安全設計
- 前提条件の不一致や操作中の検証エラーが発生した場合、CLIは非ゼロ終了コードで停止します。
- 自動再試行、Undo（元に戻す操作）、自動修復は行われません。
- 途中で処理が失敗した場合、一部の編集のみがエディタ上に残っている可能性があります。その場合は自動処理を行わず、人間が現在の全文を読み直して状況を判断してください。
- 実行中に予期せぬダイアログや未保存警告が表示された場合も、自動で承認や閉鎖は行わず停止します。
- 共同編集者による割り込み入力やエディタの自動補完によって意図しない変更が入った場合も、全文照合不一致として直ちに停止します。

### 保存に関する注意事項と検証状況
- 本CLIが確認するのは「編集直後のエディタ全文の一致」であり、Overleafサーバへの保存完了や再読み込み後の永続化とは区別されます。
- サーバへの保存状態はOverleafのUI画面上で作業者が目視確認してください。保存確認を目的とした自動リロードは行いません。
- 数式環境、日本語（マルチバイト文字）、長文ファイル、Track Changes有効環境、自動補完が動作する環境下での挙動、および保存保持の確実性については実機未検証です。
- 短いASCII文を使った比較では、主操作の計測区間合計で、検索方式は先頭から矢印キーで移動する方式の約2.4倍の速さでした。この結果は一般的な性能や安定性の保証ではなく、特定モデルに起因する問題を解消した証拠でもありません。
