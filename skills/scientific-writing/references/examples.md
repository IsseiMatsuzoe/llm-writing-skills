# 具体化する例と、そのまま残す例

以下は編集の判断を示すための架空の文章です。実際の原稿・研究結果・モデル評価の記録ではありません。

## 1. 操作対象を明示する

前提：この節は、学習率とバッチサイズを調整した方法を説明する。元資料は両者を明示している。

修正候補：

> We performed joint tuning.

読者は、何を同時に調整したのかを前の説明から拾い直す必要がある。そこで、対象を示す。

> We tuned both the learning rate and the batch size.

ここで変えたのは対象の提示方法であり、調整した対象や手法ではない。元資料に対象がなければ、この具体化は行えない。

## 2. すでに明確なら、残す

同じ前提で、原稿が次のように書かれている場合。

> We jointly tuned the learning rate and the batch size.

操作対象は文中で明示されている。“jointly”があるという理由だけで直す必要はない。修正量を増やすより、明確な原文を残す。

## 3. 関数と関数値を区別する

前提：文中の$f$は、定義済みの目的関数であり、この箇所ではその関数そのものを説明している。

> We define the objective function $f$ as follows.

この文を、具体的に見えるという理由で“objective function value”へ変えると、関数と値を混同させる。具体化は、意味を変えない場合に限る。

## 見直しの基準

- 曖昧な操作対象を具体化できるか。
- すでに明確な文章を、禁止語探しで不必要に変えていないか。
- 元資料にない対象を補ったり、関数を値へ変えたりしていないか。

これらは評価時の判断基準であり、この例を収録しただけでスキルの有効性を検証したことにはならない。
