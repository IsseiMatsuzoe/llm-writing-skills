# Scientific Writing

論文・研究レポートを、読者が対象・条件・主張と根拠を追える文章にします。事実と意味を保ち、依頼された範囲で構成と表現を組み直します。

## When to use

- 科学的な原稿を、提供資料から執筆するとき。
- 論文や研究レポートを、意味を保って推敲するとき。
- 一般向け紹介文、広告、創作の文体調整を主目的とする作業には使いません。

## Procedure

### 1. 読者・資料・編集範囲を把握する

想定読者、文書の目的、執筆か推敲か、構成変更の可否を依頼から把握します。判断を左右する不足だけを確認します。個別の用語指定や投稿先の要件は、その適用範囲で優先します。

### 2. 主張と根拠から構成する

提供資料から、何を明らかにしたいか、何が根拠か、どの条件で成立するかを整理します。必要な定義や前提を、読者がそれを使う前に理解できる順に置きます。原稿がある場合も、意味の保持を元の文順の保持と同一視しません。

数式、数値、単位、固有名詞、識別子、引用、帰属、成立条件、主張の強さを保ちます。観察・計算結果・解釈・予測を区別します。資料にない結果や引用で不足を埋めず、著者への確認事項に分けます。

### 3. 対象を特定できる文章を書く

同じ科学的対象には同じ用語を使います。表現の変化や短さのために、必要な専門語の繰り返しを避けません。

一般概念と具体的な量、関数と関数値、配列と各成分、時刻と時間区間、操作と操作対象を区別します。抽象的な理論の説明を、特定の実装例へ一律に置き換えません。

段落の主張と式・計算・観測・引用を結び付けます。図表の説明は本文の比較や議論と対応させ、記号・凡例・参照を照合します。提供されていない図表を確認済みとは扱いません。

### 4. 書いた後に、読者の立場で点検する

執筆とは別の点検工程として、完成した本文を読み直します。

- 比較・計算・微分・最適化などの操作について、何を何に対して行うかが分かるか。
- 操作を短く呼び直した箇所で、読者に対象を拾い直させていないか。必要なら具体名を戻す。
- 簡潔な表現で十分明確な箇所まで、機械的に展開していないか。
- 原稿・資料と比べて、条件・例外・因果関係・主張の強さ・引用の帰属が変わっていないか。
- 結果の説明と著者の解釈を区別できるか。

判断に迷う場合は、[具体化する例と残す例](references/examples.md)を読みます。単語の存在や修正件数だけで合否を決めません。

### 5. 本文と確認事項を分けて返す

本文は読者に渡せる形にします。編集理由、資料の不足、科学的判断が必要な不整合は、著者への短い報告に分けます。ただし、研究の適用条件や限界は本文に残します。

本文だけを求められた場合は、編集報告を本文へ混ぜません。重要な不足があるため確かな本文を書けない場合は、先に確認します。

## Pitfalls

- “joint optimization”などの語自体を禁止しません。省略によって読者が何を復元する必要があるかで判断します。
- 用語を具体化するために、新しい仕組みや科学的事実を推測で付け足しません。
- 執筆・推敲の依頼は、追加実験、原稿への直接反映、投稿・公開の許可ではありません。

## Verification

提出前に工程4を実際の出力へ適用し、原稿・資料との意味の対応を確認します。点検したことと、科学的妥当性の検証を完了したことは区別します。資料が不足して照合できない箇所は、確認済みと報告しません。
