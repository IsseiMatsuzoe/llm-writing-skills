# LLM Writing Skills

**意味を守り、読者が推測しなくてよい文章へ。**

LLMによる執筆・推敲を、長い禁止語リストではなく、目的・編集手順・提出前の点検で支えるためのスキル集です。Issei Matsuzoeが、文章の読み比べと実際の利用を通じて育てていきます。

## 考え方

- **事実と意味を守り、構成には自由を持たせる。** 元の文順を残すことと、意味を保つことを区別します。
- **読者に対象を復元させない。** 何を比較・計算・最適化したかを、必要な箇所で明示します。
- **論文と一般ドキュメントを分ける。** 用語の反復、説明順、根拠や留保の扱いを、読者と目的に合わせます。
- **執筆と点検を分ける。** 原則を読んだだけで終わらず、出力した文章への適用を最後に確認します。
- **直さない判断も残す。** 短い表現が十分明確なら、機械的に長くしません。

## スキル

| スキル | 用途 |
| --- | --- |
| [Scientific Writing](skills/scientific-writing/SKILL.md) | 論文・研究レポートの執筆と推敲。対象・条件・主張と根拠の対応を点検します。 |

現在は論文用スキルの試作版です。一般ドキュメント用スキルやプラグインは、まだ含めていません。

## 使い方

1. スキルの本文をAIに読み込ませます。スキル対応のホストでは、そのホストの方法で登録・呼び出してください。
2. 原稿または執筆用の資料と、読者・目的・変更してよい範囲を渡します。
3. 本文と、必要な場合だけ別に返される確認事項を読み、採用を判断します。

依頼例：

```text
Scientific Writingの指針に沿って、次の原稿を推敲してください。
想定読者は同分野の研究者です。構成や説明順の変更はできますが、
数式・条件・科学的主張は保ってください。本文と著者への確認事項は分けてください。
```

GitHubのリンクを渡すだけの場合も、AIがリンク先本文を実際に取得できる必要があります。登録先のスキルは、GitHubを更新するだけでは更新されるとは限りません。

## 判断例と検証

[判断例](skills/scientific-writing/references/examples.md)には、具体化する例と、そのまま残す例を収録しています。例文は公開用に作成した架空の文章で、実際の研究結果や比較実験の出力ではありません。

スキルの形式やリンクの確認と、文章品質の評価は別です。この初期版について、モデル横断の品質比較や、見落としを防ぐ効果はまだ検証していません。今後は、モデルへの実際の入力、出力、採否の理由、変更した指針を区別して改善します。

非公開の原稿・会話ログ・認証情報は、このリポジトリに含めません。スキルは執筆を支援する指示書であり、科学的内容の妥当性や投稿先の要件を自動で保証するものではありません。
